02 / CONNECTIONS

Five layers. One shared workflow.

Combine the building blocks to suit the task.

The framework organises a shared CAD vocabulary and capabilities that can be combined as needed. Its smallest useful unit is a concrete task with defined inputs and a traceable result.

Five layers

Layer Responsibility Prevents
Core Source, revision, units, identity and evidence Confusing an old generator with the current native model
Skills Selecting and executing the appropriate workflow Loading every tool for every request
Adapters Backend operations and error handling Mixing transport details into general design rules
Profiles Design and manufacturing parameters with provenance Presenting personal settings as universal material rules
Examples and checks Observable behaviour and known failure cases Documentation without verifiable applications

Three independent profiles

The design language defines colour roles, selected edges, labelling and form families. The manufacturing profile describes the actual process and, separately, provisional screening thresholds. The interface profile protects fastenings, fits, motion envelopes and load paths.

A profile change affects only its own responsibility. A different colour must not change a screw's insertion direction. A larger print bed does not authorise silently merging parts that the user wants to keep modular.

One maintained source per rule

Shared assembly, fit, project layout and print preparation rules live in knowledge/. Backend details stay with their skill. Imported field notes are identified as historical sources; their personal defaults do not automatically become requirements.

This workbench does not overwrite the previously installed skills. Future framework changes are maintained in this repository. Installation into an agent host is a separate, later step.

Until then, use the framework as a complete directory. Individual skill folders are not independent installation packages because they refer to knowledge/, profiles/ and other skills. A future installer must include those shared resources and preserve or resolve their references.

Keeping the scope focused

The framework adds no CAD kernel, general workflow execution engine or automatic cloud synchronisation. Native applications retain their existing APIs and capabilities. Concrete helpers cover the consolidated checkers, profile resolution, the native joints example and local documentation.

The website obtains its content from Markdown and the catalogues. Text is included in the static build, so viewing it requires neither a build server nor an internet connection.

Onshape CAD

Read Shared project and evidence conventions and the current project's source/assembly state. Use onshape-bridge when the configured transport is the local session bridge.

Native design and revision

Read FeatureScript and geometry field notes for backend-specific operations, coordinate bases and Boolean pitfalls. Those notes contain historical project recipes; dimensions, bed sizes and style values are examples, governed by the current project's profiles.

Before editing an existing Feature Studio, capture the live native features and source reference. Preserve user finishing features and downstream dependencies. A microversion-pinned custom feature needs its consumed namespace updated and verified after a source upload. See revision workflow.

For adapters and shared variants, align mounting axes and seats first; read retrofit and variants and assembly review. Select functional parts semantically, not by their position in an API array.

Verify part count, bounds, changed contours and protected interfaces. Volume is a useful change signal, not a shape identity. After topology changes, reacquire queries and inspect all affected assembly references; repair only broken references. Verify nested leaf poses after applying assembly transforms.

Style is an explicit profile choice. The historical workshop edge family is available as workshop-042; it does not override functional edges or load paths.

Keep source revisions, exports and actual checks together. Use sharing notes only when a review artifact is required. This task does not require changing unrelated documents.

Onshape session bridge

This is an adapter for the existing Electron/Jarvis setup. It is not a universal Onshape connection requirement. Endpoint and runtime locations come from the active project or environment.

Read transport field notes for the known setup and recovery for timeouts and sharing. Historical account windows and measured rate limits are observations, not current guarantees.

For live work, reuse the running signed-in app, inspect health and current budgets, then issue requests sequentially. Keep one consuming writer for this session adapter. If a write times out, reconcile the destination state before retrying; retain the uncertain operation across interrupted work.

Respect an explicitly selected session transport. A connection failure must not silently select API-key authentication or change the user's account configuration. Use the recipient's own sign-in when setting up a new installation.

Responses and request bodies have different binary behavior in the inspected implementation. A successful upload status is insufficient: download and hash the artifact. For generated PDFs on the UTF-8 request bridge, see the manual transport helper.

The Electron app and Jarvis runtime are separately installed dependencies, not duplicated into this framework. The framework can be read and its local helpers tested without either application. See scope and dependencies.

Build123d / cad-khana

Read Shared project and evidence conventions. Keep pure part builders, named physical occurrences, explicit units and parameter-derived poses. The cad-khana runtime is a separate dependency; this repository bundles its current skill knowledge.

Read API, diagnostics and worked patterns only for the operations being used. Build123d reference and standard parts provide backend details. Inspect the installed CLI before relying on historical commands.

The current library's assembly module is cad_khana.mechanism.assembly; mechanism checks are in cad_khana.mechanism.check. The older core.assembly README example is not the current import path.

from cad_khana.mechanism.assembly import Assembly

Declare intended clearances and interferences against the actual parts. Use narrow, explained contact allowances; a waiver is not a fit test. Rebuild the final exported slicer files after geometry changes so output folders do not silently diverge.

Read cad-fdm-design for manufacturing work. House-style values from old projects are optional profiles, not implicit library requirements. Native viewer topology selections refer to one pushed snapshot and must be resolved again after rebuilding.

The source notes include joint animation, GLB, drawing, orientation and diagnostic details. Use those capabilities as needed; do not invoke every check for a documentation-only change.

FDM design & preparation

Read Shared project and evidence conventions. Use the user's selected CAD backend and actual machine/material configuration. Material, fastening method, part count and permitted mating-part changes are separate constraints.

Choose the bed face before detailing. Preserve functional seating faces, load paths and motion. For tight assemblies, read assembly review. For selecting or constructing mating joint geometry, use cad-joints. For snaps, preload or slide-in retention, read fits and retention. For profile resolution, print files and actual extrusion evidence, read print preparation.

Keep nominal design values, calibrated process measurements and historical example dimensions distinct. Use the project's manufacturing and design-language profiles. The workshop-042 style is an optional preference, not a process rule.

Construction field notes contain local Build123d/OCC pitfalls, connection recipes and historical prototype dimensions. Apply only the relevant pattern and confirm it against the current material, orientation and interfaces. Project layout applies to longer work.

Available local helpers

  • Profile resolver: resolve inherits and ordered include dependencies, detect missing/cyclic inputs, retain child overrides.
  • Geometry screening: sampled mesh checks with explicit findings and incomplete status.
  • Geometric STEP screening: native solids and explicit inlay handling.

The profile resolver produces data for review; it is not a machine-specific G-code generator or a replacement for slicer compatibility handling. Keep actual machine identity and start/end routines under the slicer's control. Verify the exact final 3MF and its deposited layers.

Record printing, physical assembly and load testing separately from file preparation. Commands here do not dispatch physical jobs.

CAD Joints

Read shared evidence conventions and the relevant sections of joint selection and verification. Start with the load direction, required freedoms, assembly access and whether disassembly must be possible. Separate geometric restraint, friction/preload and any added locking element. Classify assembly as rigid, elastic or a combination before choosing a verification method.

Use the project's authoritative CAD backend. Route native Onshape construction to onshape-cad and its session adapter; use cad-fdm-design for print pose, material and slicing. Keep design-language detailing outside protected mating faces.

Workflow

  1. Identify the members, supported loads, remaining motion, assembly order, available insertion space and service access. Ask only for missing constraints that change the choice.
  2. Distinguish source observations, measured dimensions and proposed reconstruction values. Link the original reference and relevant timestamp. A video demonstration is not a transferable strength rating.
  3. Construct both mating parts from common reference geometry. Define which part owns the allowance and its direction: per face, diametral, profile-plane or normal to the surface. Do not offset both parts inadvertently.
  4. Check the complete assembly and removal paths, including keys, adjacent parts and stops. End-position nonintersection alone does not prove assembly. For elastic snaps, record free, maximally deflected and seated shapes, identify the compliant region, and justify allowable strain through an appropriate model or measured coupon. A rigid overlap test cannot establish elastic assembly. Preserve failed path findings and state the sampling resolution.
  5. Verify native feature status, expected solid count, valid geometry, pairwise interference and revision-bound exports. Record transforms between assembled, separated and print poses explicitly.
  6. Prepare a small clearance series in the intended material and orientation. Keep CAD clearance, measured fit, insertion force, repeated assembly, creep and load testing as separate evidence levels.

Use fits and retention for snaps, preload and compensation; assembly review for access and completeness. The Printed Joints Lab contains independent native reconstructions and their actual verification status. It is an example library, not a validated catalogue of structural joints.

For bending and tensile applications, examine the weakest root, remaining socket wall and layer-normal opening load. A longer engagement or steeper wedge does not by itself establish adequate strength. Compare matched specimens and a continuous control before ranking designs.

For thin panels, separate connectors and rim clips, consult the additional reference review. Keep these reviewed references distinct from the native lab: they have no reconstructed CAD or physical verification yet.

CAD design system

Keep three independent layers: design language, manufacturing and protected interfaces. Read Shared project and evidence conventions and the existing project profiles. Function and established constraints take precedence over generic visual defaults.

Choose the work: define a language, apply it to the requested part family, or calibrate a process with a relevant specimen. Read project integration, functional colour and checker limitations as applicable.

Profiles live in the framework's profiles directory. Generic profiles are uncalibrated starting points. The workshop-042 and instrument-style profiles describe different design languages. Do not automatically combine their edge treatments.

For each affected part, retain a ledger of role, physical colour, selected faces, protected geometry, print pose and evidence. Distinguish physical filament colours, CAD appearance and temporary instruction highlights. Never treat a graphic grid as permission to move purchased hardware or a verified interface.

Screening

Run commands from the framework root:

uv run python skills/cad-design-system/scripts/check_mesh.py part.stl --mfg profiles/manufacturing/fdm-bambu-a1-0.4.yaml --up +Z --json report.json
uv run python skills/cad-design-system/scripts/check_step.py part.step --mfg profiles/manufacturing/fdm-bambu-a1-0.4.yaml --up +Y --json step-report.json

Exit 0 means no findings within sampled scope; 1 means findings; 2 means incomplete analysis. Preserve raw findings. A declared orientation must itself fit; a hypothetical rotated fit is reported separately. Structural thin solids must not be silently exempted as inlays.

The shared checker combines Sparky's body/orientation/error handling with Distributor's bounded raster and anchored-lip checks. See consolidation decisions. No screen result establishes physical strength or fit.

The supplied style tile is a generic enclosure demonstration. Custom crush-rib, belt-clamp or wheel-stack fits require specimens made from the actual interface. Read historical detailed guidance for additional source context.

CAD assembly manuals

Read Shared project and evidence conventions. The manual is a reproducible output of CAD source, a build sequence and a maintained illustration recipe. Mechanical redesign, machine operation and public sharing need their own task scope.

Choose the relevant branch:

  • Assembly process and data: source hierarchy, purchased units, stage ownership and inventory.
  • Illustration and layout: page density, insertion arrows, readable hardware and parts trays.
  • Rendering styles and colour: stable physical roles versus temporary step highlights.
  • Local tooling and examples: the existing Onshape adapter, publication verification and PDF transport.

Plan real preassemblies and tool access before polishing pages. Native stages store completed assembly poses; explosion offsets belong to the illustration recipe. Preserve the source master and user additions. Resolve semantic identities after topology changes instead of trusting array order.

Use actual exported CAD geometry and consistent cameras. Inspect every rendered page and reconcile quantities of CAD solids, physical purchased units and handled assembly items. Neither a posed assembly nor an animation proves a collision-free insertion path.

The previous two-steps-per-page layout and instrument palette are editable example defaults. Layout data and render presets are bundled. They do not constitute a standalone renderer; Sparky and C2 remain the worked implementations documented in scope.

The PDF transport helper is bundled for generated PDFs on the known UTF-8 upload bridge. Verify downloaded bytes. Skip the encoding workaround on a binary-safe transport.

Fusion / fusion-khana

Read Shared project and evidence conventions. The existing Fusion workflow rebuilds from a maintained part program. Confirm that this source-authority model applies before clearing an existing document; a natively edited document must not be overwritten by an older generator.

Read Fusion API and source-program field notes for library operations, volume assertions, module reload behavior, coordinate conversion and shared-application pitfalls. The application's raw units and the wrapper's millimetres are distinct.

Before a rebuild, identify the intended document and affected components. Preserve source parameters, imported hardware and the user's constraints. A failed build must retain its actual exception and must not be saved as an accepted result.

Use geometric identities, real component bounds and relevant motion checks. A screenshot of whichever document is currently active cannot establish the intended document's state. Account for modal dialogs and the shared single-threaded application.

Use assembly review for tight mechanisms and cad-fdm-design for printing. Slicer and structural mesh tools are independent of Fusion.

The Fusion runtime is separately installed and was not started to prepare this documentation. Historical absolute paths and machine examples in the field notes are setup references. See scope.

Scan → parametric CAD

Read Shared project and evidence conventions and scan field notes. Use the actual photos and scanned surfaces to establish topology, marker artifacts and missing data before fitting geometry. Scanned coordinates are not automatically world-aligned.

Clean unwanted turntable geometry, register scans, establish a canonical frame, then measure sections and functional features. Separate the simplest plausible base form from local ribs, grooves and other features. Preserve uncertainty from acquisition and registration.

Fit and test design hypotheses. Compare both directions of surface deviation and inspect local zones; global median deviation can hide an unacceptable fit at a mounting surface. Sample within triangles so comparisons do not merely measure tessellation vertices.

An exact faceted mesh-to-BRep conversion and a reconstructed parametric model serve different goals. The STL2STEP prism experiment is only suitable for genuine extrusion-like geometry; compare bounds, topology and volume before accepting it.

The source scan-toolkit and STL2STEP workflows are external runtime dependencies. Historical Python/wheel statements are observations of that environment; verify the installed versions when setting up another machine. No physical fit claim follows from a scan/CAD distance map.

Mosey — illustrated interpretation, references and CAD rules

Mosey 0.1 combines a clear silhouette with large, tactile controls and calm colour fields. A recess, bail, broad facet or folded shell gives an object character while supporting its use.

The CAD profile translates this idea into reusable rules. The illustrations below show our interpretation applied to other objects.

Original vector illustration, not to scale. Hand controller: a calm body and one large rotary control. Desktop stand: a few broad facets and a distinct adjuster. Tray: a supporting shell also forms the foot and grip space. These drawings explain the design language; they have not yet been developed into CAD parts or verified mechanisms.

What the reference actually establishes

When retrieved on 10 September 2026, the Mosey gallery contained 88 form studies in six sections. The site identifies them as AI-assisted concepts, with dimensions and mechanisms still in development. This interpretation examined 18 representative renders across all six sections and preserved the original images with provenance and SHA-256 hashes.

We adopt a visual grammar. Stated target dimensions, depicted materials and suggested mechanisms are not measurements or manufacturing evidence. The profile is our interpretation of the references, not an official specification from the website.

Six references to inspect

Clamp — the body serves a second purpose

The bracket makes the relationship between enclosure and mounting immediately visible. Our interpretation: a mount or grip may define the main form. Its section, thread and clamping force still require independent mechanical design. Original Clamp study.

Cairn — distinct planes instead of rounding every surface

A few large planes and a distinct foot create a calm body. Our interpretation: broad facets are an equally valid Mosey variant. The form may respond asymmetrically to grip and control travel. Original Cairn study.

Saddle — negative space shapes the object

The recess contributes to the silhouette and provides hand contact between the wheels. Our interpretation: generous, useful negative space can carry more identity than applied decoration. Original Saddle study.

Chamfer — broad facets, quiet details

The scale difference between broad exterior facets and small openings keeps the form readable. Our interpretation: main form, hand contacts and technical details operate at different scales. Original Chamfer study.

Sling — a soft addition to a solid core

Strap and body remain distinct elements. Our interpretation: textile or elastic contacts can complement a calm base form; their attachment belongs to the mechanical design. Original Sling study.

Duo — colour can express roles

This study has more colour fields than the calmer examples. Our interpretation: three designed colour roles are a useful starting point, not a claimed law of the reference. Additional colours need an understandable purpose. Original Duo study.

Application and verification

  1. Record function, purchased parts, assembly and protected surfaces.
  2. Choose a form variant and one useful main detail.
  3. Shape free exterior surfaces; assign colour roles and calm parting lines.

What should make the design recognisable

The silhouette remains understandable without colour. The characteristic detail helps the user. Colour fields follow clear roles. Seams and labels do not dominate the main form. Visible metal parts may remain metal; vents, screws or a camera opening are added only when function requires them.

A standard pastel box alone does not fully express this language. Nor does adding as many flower-shaped knobs, arches and grooves as possible. Its identity comes from the combination of calm form, tactile controls and one useful design idea.

03 / Distributor · Contact study R8

A plug joint is not a bonded contact

Actual contact surfaces, print directions and modelling assumptions determine what an FEA result means.

In the documented R8 study, two platforms and two posts form the actual four-part section. All three plug-in joints transfer load through unilateral contact on real CAD faces. The earlier rigid coupling represented a different mechanical assumption.

The modelling decision

The faces can open and slide. Print orientation is considered for each part; effective material properties and friction are assumptions. The model includes CAD clearance and elastically modelled ribs, but no physically calibrated insertion process.

In the saved 1 kg scenario with assumed friction, the study gives approximately 3.97 mm maximum vertical displacement. This value belongs to that load case, support arrangement and R8 geometry. The image exaggerates deformation by a factor of five.

Findings and limitations

The report checks solver progress, equilibrium and sensitivity to contact stiffness. A full mesh-refinement study of this contact model was still open. PLA creep, plastic yielding and actual load capacity are not established by these results.

Later CAD revisions must not present this value as a new simulation of their own geometry. The framework's FEM extension remains a documented study for now.

Transferable rule

A simulation must identify geometry, contact, material, orientation and load together. “FEM checked” without this connection is not a traceable claim.

Functional surfaces and local openings receive their own checks. A global average surface deviation can conceal important local errors. Sample points inside CAD triangles so that the check does not confuse tessellation structure with geometry.

How two printed parts hold together

Eight native joint principles with assembly paths, parametric clearance and traceable geometry verification.

The three NeedItMakeIt videos provide the starting point for our collection of eight parametric teaching models. Each model is available in Onshape in assembled and separated views. Blue identifies partner A, orange partner B; ochre identifies the two additional wedges. These colours describe roles, not verified materials.

Open the Onshape document. The study uses the transcripts and selected CAD and assembly frames from the three sources; the original Fusion files were not reused. Our models explain the principles using a shared set of dimensions. They are not dimensionally identical copies and have not been approved for a specific load.

The shared basis

X runs along the bar, Y across its width, and Z through its thickness. Most variants start at 100 × 28 × 20 mm. The shear in J03 also changes the end faces; J08 is 120 mm long. The feature exposes joint number, nominal profile offset and separated view. Geometry parameters such as radii and angles are in the readable FeatureScript.

The default 0.10 mm is a geometric starting point, not a calibrated print setting. In the straight variants, the female profile is expanded in the sketch section; the curved variants combine radial body clearance with the profile offset. The keyed scarf accounts separately for scarf faces, wedge dimensions and channel dimensions. The nominal value therefore does not describe a uniform three-dimensional normal gap everywhere.

The separated views reveal the shapes. They are neither the simulated assembly paths nor final print orientations. Sharp roots and missing lead-in chamfers require deliberate revision before a loaded application, while preserving the protected interlocking geometry.

Joints: connections as construction knowledge

A joint is described by its geometry, assembly path, manufacturing process and intended load case. Its name alone is not enough to select it. The cad-joints skill guides these decisions; the Printed Joints Lab illustrates them with native Onshape examples.

Three distinct effects

Geometric interlocking prevents a particular relative movement through engaging faces. A dovetail can prevent separation across its sliding direction while remaining free along that direction.

Frictional retention and preload require contact forces. A tapered assembly path can become tighter with further insertion. Whether the joint holds by itself also depends on friction, deformation, surface condition and load. An angle alone does not establish self-locking.

Retention limits a remaining movement through a stop, snap hook, transverse wedge, pin or cover. Its assembly and subsequent access are part of the design. A snap hook must not be declared assemblable by assuming excessive elastic deformation.

This is a selection guide, not a strength ranking. Printed threads, bayonets, pins, magnet pockets and adhesive joints can extend the knowledge later; the first native collection covers the three linked video sources.

Shared geometry and one clearance owner

Derive male and female partners from the same centreline, surface or profile definition. An independent second sketch can introduce unnoticed differences, particularly on inclined or curved surfaces. Then assign the clearance to exactly one partner.

Record whether 0.10 mm means per flank, total width allowance or profile offset. An offset in a sketch section does not automatically produce a constant normal gap on drafted or curved faces. Nominally positive clearance does not guarantee a printed fit either.

A small trial series could compare 0.05 / 0.10 / 0.15 / 0.20 mm profile offsets. These are proposed search points. Keep material, nozzle, layer height, extrusion width, wall count, orientation, seam position and slicer compensation constant and record them. Measure first, then transfer the chosen value into the specific manufacturing profile.

Assembly is a path

Checking the final position is insufficient. Specify the moving and fixed components, axis or translation, and installation order of the retainers. Check the entire path from fully separated parts to the final position. An exploded view illustrates parts; it does not prove that path or define a print orientation.

For tapered profiles, the smaller end must enter the larger opening first. With opposing flanks, draft signs can reverse even though both bodies share the same assembly movement. Curved guides also need room for the attached bar ends to sweep.

A numerical path test states its distance or angle increments, volume tolerance and CAD revision. There is a gap in the evidence between samples. An intentionally incorrect movement provides a countercheck: does the test detect the expected engagement there?

FDM and load

First check the remaining section at tooth roots and socket walls. More engagement length spreads contact but cannot indefinitely compensate for a thin root or one vulnerable to layer separation. A steeper wedge also increases the spreading effect on its socket.

Choose print orientation together with the load path and mating faces. Support contact, bridge undersides, elephant foot and the Z seam can impair a good CAD fit. Relief chamfers and small radii must not remove protected seating or locking surfaces. Specific compensation and print preparation are covered in Fits and retention and Print preparation.

A meaningful comparison needs equal bar dimensions, equal support and load application points, identical print conditions and multiple specimens. An unbroken specimen used as a control reveals the cost of introducing the joint. Alongside maximum load, assess stiffness, permanent deformation, fracture pattern, repeated assembly and sustained-load behaviour.

Extend the verification method before adding native clips

The existing lab checks rigid bodies moving through sampled translations and rotations. A snap fit deliberately passes through a state where its undeformed solids overlap. Treating every overlap as failure rejects useful snaps; simply ignoring it can accept a clip that must break to assemble.

Use a justified deformation model or a measured coupon to establish acceptable strain; retain rigid interference checks for surrounding parts and tool access. Identity, units and pose

A part has a semantic identity, such as “right bearing carrier”. Native IDs and array positions map to that identity. The same ID can refer to changed geometry; a new ID can replace an otherwise unchanged part.

Native model coordinates, assembly pose, print pose and illustration offset are different data. Every transform has a known direction and unit. Check orthogonality and determinant +1 for rotations; mirroring is a separate design operation.

STL does not contain reliable explicit units. Record the unit from the export workflow and verify it against actual dimensions.

Rule precedence

  1. Explicit task instructions and protected mechanical interfaces.
  2. Verified native geometry and the purchased components actually used.
  3. Calibrated process data with documented measurements.
  4. Agreed design-language rules.
  5. Uncalibrated example values and historical cases.

An approved material does not imply approval of a particular joint. A style profile does not determine the number of screws. A manual does not require geometry changes when only its page layout is being revised.

Bind results to evidence

Exports are bound to their source, revision, settings and geometry hash. Inspection results apply to those exact inputs. When inputs change, renew the affected evidence; unchanged results may be reused when their identity is demonstrated.

Verification distinguishes the evidence types. Project layout describes an appropriate file structure for longer tasks.

A recipe selects existing capabilities and their handoffs. It does not require a complete development cycle for every small change.
