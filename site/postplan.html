Read me: what Toolroom is

A CAD knowledge base and skill framework for AI-assisted design. Toolroom keeps the reusable know-how of designing, checking and manufacturing parts in one place so that an agent loads the right rules for the task instead of guessing.

The name is the workshop metaphor: a toolroom is where the jigs, gauges and fixtures live that make the shop's work repeatable. Here the jigs are skills, the gauges are the knowledge base with its verification rules, and the fixtures are profiles that describe a machine, a style or a workstation. Toolroom is not a CAD kernel and does not run machines. It tells an agent what to do, where the reasoning is, and which evidence counts.

Start: open index.html for the offline documentation, or read the architecture. Local preview:

uv run python tools/serve.py

Then open http://127.0.0.1:4176.

Using it with an agent

Skill folders are entrypoints, not standalone packages: they link into ../../knowledge and ../../profiles. Install them by symlinking the folder from a checkout, for example ln -s "$PWD/skills/cad-fdm-design" ~/.claude/skills/cad-fdm-design, so the links keep resolving. The older skills already installed under ~/.claude/skills stay independent until they are replaced; provenance/originals/ preserves their entrypoints for comparison.

The workstation profile in profiles/environment/ describes one specific setup (endpoints, default printer, library paths). Another user replaces it with their own copy of the template.

Rebuild the documentation and run the checks

uv sync
uv run python labs/checker-lab/build.py

uv run python -m unittest discover -s tests -v

The HTML is generated from Markdown and the three catalogs (catalog.json, knowledge/catalog.json, labs/catalog.json). Edit those sources, never site/data.js. The validator checks every local link and heading anchor, the catalog contracts, image and evidence hashes, and that the generated files are current.

02 / CONNECTIONS

Five layers. One shared workflow.

Combine the building blocks to suit the task.

Toolroom separates four kinds of content that are easy to mix up: reasoning, procedure, data and evidence. Each has one home, one catalog and one way of being verified.

Layers

Layer Directory Responsibility Prevents
Knowledge knowledge/ Rules with their reasons, evidence and limits, independent of any CAD backend Restating the same rule in five skills with five wordings
Skills skills/ Thin entrypoints: when to load which knowledge, and how to execute in Onshape, Build123d or Fusion Loading every tool and every reference for every request
Profiles profiles/ Design languages, manufacturing processes, protected interfaces and the workstation profile Presenting one person's printer or style as a universal rule
Labs labs/ Reproducible experiments with their own inputs, outputs and hashes Documentation without anything that can be re-run

How a task travels

  1. The agent matches a task to a skill entrypoint. The entrypoint states when it applies and when it does not.
  2. The entrypoint names the knowledge articles to read for this task, the profile to resolve, and the backend references it needs.
  3. The knowledge article states the rule and the evidence the result must carry. The profile supplies numbers with provenance.
  4. The result is bound to its inputs, revision and geometry hash. Verification states are no_findings, review or incomplete; "not run" is a separate state and never a success.

A layout change of a manual does not require a CAD rebuild. A different design language does not authorise moving a screw. A larger print bed does not merge parts the user wants modular. The layers make such non-consequences explicit.

Three independent profile roles

The design language defines colour roles, selected edges, labelling and form families. The manufacturing profile describes the actual process and, separately, provisional screening thresholds. The interface profile protects fastenings, fits, motion envelopes and load paths. The workstation profile describes endpoints, library locations and defaults of one specific setup. A change in one role does not change another.

Kept out of scope

Toolroom adds no CAD kernel, no workflow execution engine and no cloud synchronisation. Native applications keep their APIs. The bundled helpers are the consolidated mesh and STEP screeners, the profile resolver, the joints verifier and the documentation tools. Cloud adapters and CAD runtimes are separately installed; see scope.

The website reads only Markdown and the catalogs. Viewing it needs neither a build server nor an internet connection.

CAD workflow

Use when a CAD job spans several stages or tools: a new project, work that crosses backends, or an explicit review of how a project is organised and evidenced. Do not use when the task is one isolated edit, a layout change or a question answered by a single skill — read that skill directly.

Procedure

  1. State the requested outcome, the current project and its source authority before touching a tool. Preserve the user's selected backend, established interfaces and existing authorization.
  2. Identify affected parts, protected interfaces and the actual output. Reuse the project's native CAD when it contains user edits a generator does not have.
  3. Select only the applicable branches below. A manual layout change needs no CAD rebuild; a process profile cannot authorize a machine job or a cloud publication.
  4. Keep source revisions, exports and checks together. State unmeasured quantities explicitly and preserve incomplete results rather than rounding them up to a pass.

Onshape CAD

Use when building or revising native Onshape geometry: FeatureScript features, retrofits, shared variants, and verifying the interfaces they touch. Do not use when the question is transport, session health or metering — that is onshape-bridge — or when a local file can answer it without opening a document.

Procedure

  1. Read the project's source and assembly state first. Capture the live native features and the source reference before editing an existing Feature Studio.
  2. Preserve user finishing features and downstream dependencies. A microversion-pinned custom feature needs its consumed namespace updated and verified after a source upload.
  3. For adapters and shared variants, align mounting axes and seats before detailing. Select functional parts semantically, never by their position in an API array.
  4. Verify part count, bounds, changed contours and protected interfaces. Volume is a change signal, not a shape identity.
  5. After topology changes, reacquire queries and inspect all affected assembly references; repair only the broken ones. Verify nested leaf poses after applying assembly transforms.
  6. Keep source revisions, exports and the actual checks together. This task does not require changing unrelated documents.

Style is an explicit profile choice. The historical workshop edge family is available as workshop-042; it never overrides functional edges or load paths.

Onshape session bridge

Use when live Onshape work has to run over the configured session bridge: bringing the transport up, checking session health and endpoint budgets, reconciling a write that timed out, or verifying an uploaded artifact. Do not use when the work is local — reviewing a cached report, editing files or reading documentation needs no startup and no cloud probe. Geometry methods live in onshape-cad.

The endpoint, the app location and the start command come from the environment profile, not from this file. The adapter is built on a locally installed signed-in Electron app plus an MCP server; both are separate dependencies and are not duplicated into this framework.

Procedure

  1. Reuse the running, signed-in app. Check local health first; launch it only if it is down, from a persistent terminal that stays open.
  2. Verify the session, then read the authoritative metering counters. Note them before and after the session and compare the same reporting window.
  3. Check endpoint budgets before a batch. Make one real request to the endpoint the batch needs and inspect its forwarded x-rate-limit-remaining header.
  4. Issue requests sequentially and keep a single consuming writer for this adapter.
  5. If a write times out, reconcile the destination state before retrying — a timeout can follow a successful mutation. Carry the uncertain operation across interrupted work.
  6. For uploads, a successful status is not evidence: download the artifact and hash it. Request and response bodies behave differently for binary data in the inspected implementation.

No call may reach the Onshape servers directly. If the bridge is down, calls must fail. A connection failure must never silently fall back to API-key authentication or change the user's account configuration. If the key counter moves, something leaked to the metered API — stop and fix it. Use the recipient's own sign-in when setting up a new installation.

Build123d / cad-khana

Use when writing or editing a script that imports cad_khana, running its assembly assertions and geometric diagnostics, or interpreting its JSON output, drawings and exports. Do not use when the design lives in a cloud backend — use onshape-cad or fusion360 — or when a documentation-only change would trigger checks for nothing.

The cad-khana runtime is a separate dependency; this repository bundles its skill knowledge, not the library.

Procedure

  1. Keep pure part builders, named physical occurrences, explicit units and parameter-derived poses.

  2. Inspect the installed CLI before relying on a historical command. The current assembly module is cad_khana.mechanism.assembly and mechanism checks are in cad_khana.mechanism.check; the older core.assembly README example is not the current import path.

FDM design & preparation

Use when a part is designed or revised for FDM printing in any backend: choosing the print pose, preserving mating interfaces, judging assembly access and fits, preparing or comparing print files and inspecting actual slicer output. Do not use when the connection geometry itself is the question — start at cad-joints — or when nothing will be printed.

Procedure

  1. Establish the constraints separately: material, fastening method, part count and which mating parts may change. An answer such as "PLA" confirms the material only; it does not select a fastening scheme.
  2. Choose the bed face before detailing — see print orientation for how that choice sets strength, support and surface quality. "Vertical" is defined relative to it, and nothing may protrude below it.
  3. Preserve functional seating faces, load paths and motion. Keep design-language detailing off protected mating faces.
  4. Check access and the full assembly path, not just the final pose. For snaps, preload and slide-in retention, separate rigid location from elastic retention.
  5. Resolve the manufacturing profile explicitly and keep nominal design values, calibrated process measurements and historical example dimensions distinct.
  6. Verify the exact final 3MF and its deposited layers — printer, nozzle, filament, plate, real machine start/end G-code, estimates and preview — not the UI dropdown. Machine identity and start/end routines stay under the slicer's control.
  7. Record printing, physical assembly and load testing separately from file preparation. Nothing here dispatches a physical job.

CAD Joints

Use when two parts have to be connected and the connection is the design problem: selecting, reconstructing or dimensioning printed sliding joints, dovetails, keyed scarfs, snap fits, assembly paths, retention or comparative fit coupons. Do not use when the seam is cosmetic, or when an existing joint only has to be illustrated in an assembly drawing.

Procedure

  1. Start from load direction, required freedoms, assembly access and whether disassembly must be possible. Separate geometric restraint, friction or preload, and any added locking element. Classify the assembly as rigid, elastic or both before choosing a verification method. Ask only for the missing constraints that change the choice.
  2. Distinguish source observations, measured dimensions and proposed reconstruction values. Link the original reference and its timestamp. A video demonstration is not a transferable strength rating.
  3. Construct both mating parts from common reference geometry. Define which part owns the allowance and in which direction — per face, diametral, profile-plane or normal to the surface. Do not offset both parts by accident.
  4. Check the complete assembly and removal paths including keys, adjacent parts and stops. End-position nonintersection does not prove assembly. For elastic snaps, record the free, maximally deflected and seated shapes, identify the compliant region, and justify the strain through an appropriate model or a measured coupon; a rigid overlap test cannot establish elastic assembly. Preserve failed path findings and state the sampling resolution.
  5. Verify native feature status, expected solid count, valid geometry, pairwise interference and revision-bound exports. Record the transforms between assembled, separated and print poses explicitly.
  6. Prepare a small clearance series in the intended material and orientation. Keep CAD clearance, measured fit, insertion force, repeated assembly, creep and load testing as separate levels of evidence.

For bending and tensile loads, examine the weakest root, the remaining socket wall and the layer-normal opening load. A longer engagement or a steeper wedge does not by itself establish strength; compare matched specimens against a continuous control before ranking designs.

Use the project's authoritative CAD backend: onshape-cad for native cloud construction, cad-fdm-design for print pose, material and slicing.

CAD design system

Use when a reusable design language is defined, applied to a part family, or calibrated against a process: edge and label rules, functional colours, profile authorship, design screening and style coupons. Do not use when a single part needs a functional fix — function and established constraints outrank generic visual defaults, and a style profile never authorizes moving purchased hardware or a verified interface.

Keep three independent layers apart: design language, manufacturing and protected interfaces. Choose the work first — define a language, apply it, or calibrate a process with a relevant specimen.

Procedure

  1. Read the existing project profiles before writing a new one. Generic profiles are uncalibrated starting points, and different design languages must not have their edge treatments silently combined.

  2. For each affected part, keep a ledger of role, physical colour, selected faces, protected geometry, print pose and evidence.

  3. Distinguish physical filament colours, CAD appearance and temporary instruction highlights. A graphic grid is not permission to move hardware.

  4. Screen candidate geometry from the framework root:

    uv run python skills/cad-design-system/scripts/check_mesh.py part.stl --mfg profiles/manufacturing/fdm-bambu-a1-0.4.yaml --up +Z --json report.json
uv run python skills/cad-design-system/scripts/check_step.py part.step --mfg profiles/manufacturing/fdm-bambu-a1-0.4.yaml --up +Y --json step-report.json

    Exit 0 means no findings within the sampled scope, 1 means findings, 2 means incomplete analysis. Preserve raw findings. A declared orientation must itself fit; a hypothetical rotated fit is reported separately. Structural thin solids must not be silently exempted as inlays.

  5. The two scripts are one consolidated checker, merging the body, orientation and error handling of one source implementation with the bounded raster and anchored-lip checks of another; see consolidation decisions. No screen result establishes physical strength or fit.

  6. Custom crush-rib, belt-clamp or wheel-stack fits need specimens made from the actual interface. The bundled style tile is a generic enclosure demonstration.

CAD assembly manuals

Use when an illustrated assembly manual is created or regenerated from Onshape CAD: durable native stages, semantic part identities, explicit inventory, page layout and the maintained rendering recipe. Do not use when the task is mechanical redesign, machine operation or public sharing — each needs its own scope.

The manual is a reproducible output of three things: CAD source, a build sequence and an illustration recipe.

Procedure

  1. Plan real preassemblies and tool access before polishing pages.
  2. Keep native stages for completed assembly poses; explosion offsets belong to the illustration recipe, not to the CAD.
  3. Preserve the source master and the user's additions. Resolve semantic identities after topology changes instead of trusting array order.
  4. Render from actual exported CAD geometry with consistent cameras. Inspect every rendered page.
  5. Reconcile quantities across CAD solids, physical purchased units and handled assembly items.
  6. Neither a posed assembly nor an animation proves a collision-free insertion path.
  7. For a generated PDF on the known UTF-8 upload bridge, use the PDF transport helper and verify the downloaded bytes. Skip the encoding workaround on a binary-safe transport.

The previous two-steps-per-page layout and instrument palette are editable example defaults: layout data and render presets are bundled but do not constitute a standalone renderer. The worked implementations are documented in scope.

Fusion / fusion-khana

Use when a Fusion design is built or revised through the maintained source-program workflow: rebuilding a document from its part program, asserting volume balances, and running native assembly and motion checks against a running Fusion application. Procedure

Scan → parametric CAD

Use when a 3D scan has to become usable CAD: inspecting and cleaning the source mesh, registering scans, establishing a canonical frame, fitting primitives, separating base form from features and measuring the reconstruction against the scan. Do not use when the part can simply be measured, or when the scan is only needed as a visual reference.

Procedure

  1. Look at photographs of the actual part first. Topology is resolved in seconds from a photo and can cost an hour from scans alone; photographs also separate real form features from acquisition artefacts such as attached markers.
  2. Clean unwanted turntable geometry and register the scans. Scanned coordinates are not automatically world-aligned and the turntable is not necessarily normal to Z.
  3. Establish a canonical frame, then measure sections and functional features. Preserve the uncertainty carried in from acquisition and registration.
  4. Separate the simplest plausible base form from local ribs, grooves and other features, and model them as distinct parametric elements.
  5. Fit and test design hypotheses. Compare both directions of surface deviation and inspect local zones: a global median can hide an unacceptable fit at a mounting surface. Sample within triangles so the comparison does not merely measure tessellation vertices.
  6. Treat an exact faceted mesh-to-BRep conversion and a reconstructed parametric model as different goals. A prism-extraction shortcut suits genuinely extrusion-like geometry only; compare bounds, topology and volume before accepting it.

No physical fit claim follows from a scan-to-CAD distance map.

How to use the profiles

Design language, manufacturing and mechanical interfaces are maintained independently.

  • design-language/: Instrument, Soft Consumer, Rugged Industrial, the historical Workshop 0.42 family and Mosey.
  • manufacturing/: generic starting profiles for FDM, CNC, laser cutting and SLA.
  • interfaces/: an illustrative interface profile showing the structure of protected requirements.
  • environment/: one machine's local facts — endpoints, installed runtimes, default profiles.

The environment layer is deliberately separate from the other three. Design language, manufacturing and interface profiles describe a subject and can be reused by anyone; an environment profile describes a single workstation and is expected to be replaced. It records where a CAD runtime is installed, which port a local adapter listens on and which manufacturing and design-language profiles that machine defaults to, so no skill entrypoint has to hard-code a path or a port. Nothing there calibrates anything: a default printer entry names the machine in the room, it does not establish a tolerance.

Imported generic numbers are starting values. A field name such as measured_thickness does not turn an inherited default into a measurement. Source, material, machine, date, measurement method and result must establish the actual calibration.

The website's profile workbench illustrates roles and consequences schematically. It does not modify a CAD file or approve a manufacturing job.

Printed Joints Lab — eight native joint principles

The three NeedItMakeIt videos provide the starting point for our collection of eight parametric teaching models. Each model is available in Onshape in assembled and separated views. Blue identifies partner A, orange partner B; ochre identifies the two additional wedges. These colours describe roles, not verified materials.

Open the Onshape document. The study uses the transcripts and selected CAD and assembly frames from the three sources; the original Fusion files were not reused. Our models explain the principles using a shared set of dimensions. They are not dimensionally identical copies and have not been approved for a specific load.

The shared basis

X runs along the bar, Y across its width, and Z through its thickness. Most variants start at 100 × 28 × 20 mm. The shear in J03 also changes the end faces; J08 is 120 mm long. The feature exposes joint number, nominal profile offset and separated view. Geometry parameters such as radii and angles are in the readable FeatureScript.

The default 0.10 mm is a geometric starting point, not a calibrated print setting. In the straight variants, the female profile is expanded in the sketch section; the curved variants combine radial body clearance with the profile offset. The keyed scarf accounts separately for scarf faces, wedge dimensions and channel dimensions. The nominal value therefore does not describe a uniform three-dimensional normal gap everywhere.

The separated views reveal the shapes. They are neither the simulated assembly paths nor final print orientations. Sharp roots and missing lead-in chamfers require deliberate revision before a loaded application, while preserving the protected interlocking geometry.

J01 · Straight dovetail

J01 interlocks across the Z sliding direction. The joint remains free along Z; a product may need a stop or an additional retainer on that axis.

Construction: Flanks approximately 15°, engagement 8 mm; constant profile over a height of 20 mm. Assembly: Insert A from below along +Z.

Limits of this reconstruction: No protection against sliding out along Z; thin socket cheeks may spread.

The shared core

A task selects the required steps. The core keeps together information that can otherwise be lost between CAD, manufacturing and documentation.

Before editing, establish what is current, which parts are affected, which source is actually consumed and which interfaces remain protected.

Identity, units and pose

A part has a semantic identity, such as “right bearing carrier”. Native IDs and array positions map to that identity. The same ID can refer to changed geometry; a new ID can replace an otherwise unchanged part.

Native model coordinates, assembly pose, print pose and illustration offset are different data. Every transform has a known direction and unit. Check orthogonality and determinant +1 for rotations; mirroring is a separate design operation.

STL does not contain reliable explicit units. Record the unit from the export workflow and verify it against actual dimensions.

Rule precedence

  1. Explicit task instructions and protected mechanical interfaces.
  2. Verified native geometry and the purchased components actually used.
  3. Calibrated process data with documented measurements.
  4. Agreed design-language rules.
  5. Uncalibrated example values and historical cases.

An approved material does not imply approval of a particular joint. A style profile does not determine the number of screws. A manual does not require geometry changes when only its page layout is being revised.

Bind results to evidence

Exports are bound to their source, revision, settings and geometry hash. Inspection results apply to those exact inputs. When inputs change, renew the affected evidence; unchanged results may be reused when their identity is demonstrated.

Verification distinguishes the evidence types. Project layout describes an appropriate file structure for longer tasks.

Result states

The shared geometry checkers use no_findings, review and incomplete, with exit codes 0, 1 and 2. “Not run” is a separate documentation state and never a success.

no_findings means no issue was found within the documented inspection scope. Failed rays or an interrupted analysis leave the result incomplete, even if no thin wall had been found beforehand.

A traceable report

A report identifies the input file and hash, source and revision, selected orientation, process profile, tool version, actual inspection values, raw findings and limitations. Justified exceptions remain visible. A thin structural plate must not automatically be exempted as a decorative colour layer.

Concrete failure cases from the projects

  • A narrow free-standing underside needs an anchor. Small width alone does not make it a printable lip.
  • A part that fits only after a quarter-turn does not fit in its declared print pose.
  • Enabling support does not prove that support was actually generated.
  • A long segment labelled “Bridge” may partly rest on infill; its length is not automatically the unsupported span.
  • A bearing can be collision-free in its final pose yet impossible to insert as a complete purchased component.
  • A PDF upload may report success even though its binary data changed.

Workflow

How tasks combine skills, and how a longer project keeps sources, state and exports apart.

Combining tasks

A recipe selects existing capabilities and their handoffs. It does not require a complete development cycle for every small change.

Design a new FDM part

Requirements and interfaces → selected CAD backend → deliberate print pose → geometry and assembly checks → actual slicer profile → verified export. Give any required fit experiment its own small coupon.

Revise an existing Onshape mount

Preserve native user features → inspect mating axes and seating faces → targeted FeatureScript or native change → current body mapping → check affected assemblies → fresh exports. A stable tab alone does not prove stable geometry.

Design a product family

Functional roles and protected interfaces → selected design language → manufacturing profile → targeted face and edge treatment per part → paired views with the same camera → output bound to evidence.

Create an assembly manual

CAD snapshot and complete purchased components → manageable bill of materials → subassemblies and accessible screw sequence → durable build stages → separate illustration → PDF/web → inspect every page and quantity.

Reconstruct a scan

Review photos and scans → clean and register → reference axes → distinguish base forms from features → reconstruct functional surfaces → inspect local bidirectional deviations. A smoothed image is not dimensional evidence.

Compare structures

Current geometry and load assumptions → actual print orientations → appropriate contact/material model → equilibrium and sensitivity checks → prediction limits → suitable physical comparison. This extension currently exists in the framework as a documented project study.

Construction

Assembly access, fits and retention, joints and reusable construction patterns.

Assembly, access and load paths

Use for screwed adapters, rail carriages, belt tensioners and compact mechanisms. Derived from Sparky R4–R7 and Alternate Chute / SC15 (September 2026); the particular hardware and dimensions are examples, not universal design rules.

Retrofitting an existing interface

Measure mounting-hole axes, seating planes and the real hardware envelope before adding material. An offset bracket should not acquire little extensions merely to conceal misalignment. Set the intended flush contact and verify the axes together; if the envelopes conflict, redesign the load path explicitly. Keep purchased hardware geometry faithful to the source. A large chamfer on a printed housing can change; a real servo case cannot be reshaped to pass a check.

Connector access includes the inserted plug, insertion/removal path and cable exit/bend space. For a daisy-chained servo, check both sockets, including the one obscured by a lower bracket. A simplified servo solid may omit connectors; mark the measured/assumed plug envelope instead of reporting housing clearance as proof of connector access. Check again with the complete assembly present.

Before detailing a cheaper servo plus reduction, compare the complete option: required output torque/travel/speed, losses, backlash, bearings, extra printed parts, envelope, assembly effort and total cost. A nominal reduction ratio alone does not establish useful torque, reachable travel or economic value. Use available bearing models/inventory where suitable; order history is not proof of remaining stock. Record and respect a discarded drive branch rather than reviving it from old source files.

Before cutting access windows

Describe a feasible assembly sequence, including which parts are present at each step. If A must be fastened before B but B blocks A's fasteners, the sequence has a cycle. Resolve it in the design: separate subassemblies with a later accessible joint, captive fasteners, or a genuinely reachable access route. Do not merely write “install these screws first” when the next step makes that impossible.

Choose access together with the load path. The Sparky front-loading belt opening removed too much supporting material and was rejected as flimsy. Rear belt loading with an externally accessible tension screw was accepted. Keep a broad reacting wall/ledge, guided slider and adequate material around holes and nut pockets. Do not extend a thin cantilever solely to achieve a preferred access direction.

For a split adapter, retain support across the interface, define alignment/shear transfer where needed, and ensure fastener heads are recessed on both mating faces. A stepped split can retain the tensioner wall while sharing central plate thickness. Select the split and bed faces together; a small projecting pad can lift the entire plate off the bed.

Check three different geometries

  1. Fastener installation: actual head diameter/height, shaft, washers, nut pockets and nut insertion path. Check the head's travel separately from the thinner driver shaft. Model the straight tool approach and working space; never assume a ball-end key or a special tool the user has not specified.
  2. Subassembly joining: move the pre-fastened subassemblies through the real insertion path, with their screws and already-installed accessories present. A sensor flange or its screw head may clear the final position but block the approach. Test relevant adjustment extremes as well as the displayed pose.
  3. Operation and service: sweep all moving bodies, including newly added halves and hardware, against fixed parts. Check both travel ends and changes near collisions; use denser/adaptive samples or swept envelopes for narrow obstacles. A finite sample set is not a proof for every intermediate pose. Include a suitable overtravel negative control when checking travel stops.

Compare the complete hardware envelope against width/depth limits. Check collars, washer diameters, head protrusion and screw tips, not just the printed silhouette. Sparky's washers affected PCB clearance; a half-millimeter screw-tip protrusion also breached the width limit. Removing either from the test would hide the bug.

Choose fastener length from the real stack and available threaded depth. “Longer for more engagement” can hit internals: the longer laser screws in Sparky did. A geometrically fitting short screw is not proof of sufficient thread strength; record actual engagement and remaining physical/load validation explicitly.

Belt and bearing specifics

  • Determine whether the belt is open or endless from the physical reference. Draw separate ends for an open belt, with a fixed anchor and a guided moving anchor when that is the intended mechanism. A visually continuous reference belt must not erase the tensioning gap.
  • Check belt width, actual tooth profile and slot insertion direction. Reference tooth dimensions are a starting point for the user's real belt and print fit.
  • Prove slider insertion, tension travel, nut capture and tool access separately. Tightening must move the intended anchor in the direction that increases belt tension. Do not consume the rail's full nominal travel when the user needs less.
  • An integrated idler pedestal can remove an unnecessary separate bracket. Verify the axle stack and nut access; stationary supports/shims should bear on the intended inner race, clear rotating flanges/shields, and permit free rotation.

Evidence and handoff

Use semantic part roles for collision exemptions and moving groups. Reconcile expected printed-part count separately from hardware/reference body count. Record intentional contacts narrowly (for example simplified smooth belt envelope against tooth pockets), and investigate every other contact. Numerical slivers need a localized diagnosis; do not globally delete “small” bodies to pass counts.

A larger volume or unchanged minimum layer section does not establish stiffness. Assess the actual load path and chosen print orientation; distinguish geometric clearance, slicing, strength heuristics and physical fit/load testing in results.

Deliver a short assembly sequence, concrete fastener stack, retained parts, and replacement parts relative to the revision the user actually printed. A completed CAD export or sliced plate does not mean that a print has started.

Fits, preload and one-piece latches

Use when a printed guide rocks, a mating seam opens, or the user wants a part to snap in under slight tension. Derived from Alternate Chute / Funnel Guide R2–R4, September 2026. R4 was checked in CAD and OrcaSlicer; physical fit and retained PLA preload were still untested. Its dimensions are not general rules.

Establish the actual constraint and contact system

  • Record material, allowed part count, adjustment method and which existing parts/poses may change separately. “PLA” is not consent to add a screw. “One-piece, snaps in during insertion” excludes a separate clamp wedge for that task. Existing mounting screws may still be part of the unchanged design.
  • Identify how the part moves: lateral translation, withdrawal, rocking, or opening of a seam under load. Map the relevant degrees of freedom to contacts in the whole assembly, including the core and the opposite guide.
  • Read the current geometry and identify parts by role/source and measured features, not by array position. The first core solid in this project was a bearing holder, not the main chute body.
  • Preserve specified mounting axes, mating parts and assembly transforms. Measure the existing end stop before inventing additional seating travel. A local guide/funnel calculation omitted the core; moving the funnel inward to “pull it tight” then caused a large core collision. That candidate was rejected.

Design rigid location and elastic retention together

  1. Define which rigid faces stop insertion and resist rocking. Give bearing shoulders useful separation along the rocking lever arm and sufficient support behind them. A tiny clearance reduction alone establishes no preload.
  2. Use the latch to keep those faces seated. Check the contact normal and force direction at the existing seated pose. A latch that only blocks withdrawal may still permit the seam to open or the part to rock.
  3. Check a small virtual withdrawal: for an elastic draw latch, required deflection/strain energy should initially increase in the withdrawal direction. A tooth that unloads on withdrawal may push the part away from the stop instead. Include friction assumptions rather than relying on them silently; evaluate retention against the expected separating load.
  4. Provide a lead-in and a reachable release action. Check that the tooth clears and does not bottom against the tongue slot throughout insertion and release. A printed integral release tab can satisfy a one-piece requirement.

Use long flexures with rounded slot roots and gradual load transfer where the available envelope allows. Check both seated deflection and the higher excursion over the lead-in, including plausible print variation. Do not turn R4's tongue length, thickness, strain estimates or the usual 0.42 mm deburr into defaults for other latches. Chamfers must preserve retaining faces and the flexure root.

For PLA, describe relaxation and repeated insertion as validation needs, not a reason to silently substitute PETG or new hardware. A linear solid-beam estimate is only a screening model: record its modulus assumption, loaded length, section, deflection and orientation. Infill, perimeters, stress concentrations, temperature and time affect the printed part. It is neither an FEA result nor an allowable-strain or fatigue certification. A clearance or latch measured in one print pose does not carry over to another; see print orientation.

Verify the three states explicitly

  • Unloaded print geometry: one connected solid for a one-piece holder; mounting hole axes and reference faces retained; usable bed face, no slivers, enclosed support traps or accidental severing of the tongue.
  • Insertion/removal: sample the real path, including the peak ramp crossing, both end conditions and release. Track deformation/clearances with the mating parts present. Final-pose clearance alone does not establish insertability.
  • Seated assembly: distinguish intentional undeformed tooth overlap from rigid collision. Record partner, location and magnitude of that overlap; compare a justified deflected-tongue model and check all remaining neighbour pairs. Do not waive the entire guide/funnel pair or translate a fixed mate to make the undeformed overlap disappear. A rigid-only legacy test must be adapted to this distinction, not simply disabled.

Run the relevant cases for each funnel size and both guide positions. Record which geometry is exact and which deformation or contact calculation is an approximation. Mesh intersection volume alone is not a stiffness or retention measurement; coplanar FCL penetration reports also need a localized check.

Print and physical acceptance

Choose a broad real bed face on the final part and orient the tongue/root for the load path. Check perimeters and actual support extrusion in the slicer; see slicer preparation. State how many identical pieces are required and how many are included in the plate.

The first physical check is a complete mating set: insert fully, inspect seam opening and rocking under representative hand/load directions, and confirm release access. Repeat after several insertions and a documented hold time at the intended temperature. Compare with the user's actually printed revision. Until that is done, report “geometry/slicing checked; physical fit and retained preload open,” rather than “cannot wobble” or “permanently play-free.”

Joints: how connections hold

A joint is described by its geometry, assembly path, manufacturing process and intended load case. Its name alone is not enough to select it. The cad-joints skill guides these decisions; the Printed Joints Lab illustrates them with native Onshape examples.

Three distinct effects

Geometric interlocking prevents a particular relative movement through engaging faces. A dovetail can prevent separation across its sliding direction while remaining free along that direction.

Frictional retention and preload require contact forces. A tapered assembly path can become tighter with further insertion. Whether the joint holds by itself also depends on friction, deformation, surface condition and load. An angle alone does not establish self-locking.

Retention limits a remaining movement through a stop, snap hook, transverse wedge, pin or cover. Its assembly and subsequent access are part of the design. A snap hook must not be declared assemblable by assuming excessive elastic deformation.

Shared geometry and one clearance owner

Derive male and female partners from the same centreline, surface or profile definition. An independent second sketch can introduce unnoticed differences, particularly on inclined or curved surfaces. Then assign the clearance to exactly one partner.

Record whether 0.10 mm means per flank, total width allowance or profile offset. An offset in a sketch section does not automatically produce a constant normal gap on drafted or curved faces. Nominally positive clearance does not guarantee a printed fit either.

A small trial series could compare 0.05 / 0.10 / 0.15 / 0.20 mm profile offsets. These are proposed search points. Keep material, nozzle, layer height, extrusion width, wall count, orientation, seam position and slicer compensation constant and record them. Measure first, then transfer the chosen value into the specific manufacturing profile.

Assembly is a path

Checking the final position is insufficient. Specify the moving and fixed components, axis or translation, and installation order of the retainers. Check the entire path from fully separated parts to the final position. An exploded view illustrates parts; it does not prove that path or define a print orientation.

For tapered profiles, the smaller end must enter the larger opening first. With opposing flanks, draft signs can reverse even though both bodies share the same assembly movement. Curved guides also need room for the attached bar ends to sweep.

A numerical path test states its distance or angle increments, volume tolerance and CAD revision. There is a gap in the evidence between samples. An intentionally incorrect movement provides a countercheck: does the test detect the expected engagement there?

FDM and load

First check the remaining section at tooth roots and socket walls. More engagement length spreads contact but cannot indefinitely compensate for a thin root or one vulnerable to layer separation. A steeper wedge also increases the spreading effect on its socket.

Choose print orientation together with the load path and mating faces. Support contact, bridge undersides, elephant foot and the Z seam can impair a good CAD fit. Relief chamfers and small radii must not remove protected seating or locking surfaces. Specific compensation and print preparation are covered in Fits and retention and Print preparation.

A meaningful comparison needs equal bar dimensions, equal support and load application points, identical print conditions and multiple specimens. An unbroken specimen used as a control reveals the cost of introducing the joint. Alongside maximum load, assess stiffness, permanent deformation, fracture pattern, repeated assembly and sustained-load behaviour.

A rim clip adds an assembly-access pattern

The brief sequence does not establish a release operation, material, dimensions or fatigue life. Subtitle retrieval was unavailable; this interpretation relies on the visible sequence and metadata. Framework interpretation: record the access direction as part of the interface. A top-installed clip needs insertion space above the rim and a release route after neighbouring panels are fitted. Determine whether the clip only retains the panels or also locates them; locating surfaces should not be assumed to emerge from spring pressure. A seated clip in a short demonstration is not evidence of repeated serviceability.

Open-ring clips make compliance explicit

Joseph Willis explains a connector whose open circular ends flex through a narrower entry. The shown sketch uses 16 mm outer end diameter and a 14 mm central width. Their 2 mm difference is a total width change, not an established per-arm displacement. The source describes 0.1 mm extra space on the front/back faces; the frame at 0:37 explicitly shows a 0.05 mm outer clearance operation, resolving an ambiguous automatic transcript. Framework interpretation: keep end diameter, throat width, ring section, gap opening, depth clearance and lead-in as separate parameters. Orient the compliant shape deliberately relative to the deposited layers. Measure insertion and withdrawal forces, permanent set and behaviour after repeated assembly; assess sustained loading separately. A loop shape or a 2 mm width difference alone does not establish acceptable strain.

Extend the verification method before adding native clips

The existing lab checks rigid bodies moving through sampled translations and rotations. A snap fit deliberately passes through a state where its undeformed solids overlap. Treating every overlap as failure rejects useful snaps; simply ignoring it can accept a clip that must break to assemble.

For an elastic joint, record three states: free shape, maximum assembly deflection and seated shape. Identify the compliant region and what supplies its restoring force. Use a justified deformation model or a measured coupon to establish acceptable strain; retain rigid interference checks for surrounding parts and tool access. Report geometric reconstruction, elastic analysis, printed fit, cycle testing and load testing separately.

A useful next coupon sequence is:

  1. A panel seam with mirrored upper/lower engagement, alongside an unbroken panel control.
  2. An open-ring connector with fixed receivers and a small, documented variation in ring section and entry width.
  3. A rim clip with visible insertion and release access, tested after the surrounding enclosure is assembled.

These are proposed experiments. No native CAD, printed fit or strength result is claimed for them in this edition. See Fits and retention for the general separation of guidance, preload and retention.

Slicer preparation and review

Use when preparing printable CAD outputs or interpreting a slicer/strength report. Observed in September 2026 with Sparky's A1 / Bambu Studio / PLA Matte and Alternate Chute's OrcaSlicer / Trident comparison profiles. Recheck the installed profiles and current user request; none is a global machine/material default. Some project profiles were assumptions, not confirmed physical printers.

Preserve the actual machine profile

Bambu profile sets can use ordered include[] templates in addition to inherits. An inherits-only flattener produced plausible generic settings while dropping the A1-specific start sequence. Resolve dependencies recursively, with cycle/missing file diagnostics: inherited settings, includes in their declared order, the profile's own settings, then deliberate task overrides. Preserve the slicer's machine identity/compatibility handling; do not let template metadata select a different machine. Validate the resolved values against the installed templates.

The shared fusion-khana/tools/sliceability.py flattener historically handled only inherits. Check its current implementation before reuse. A tested adapter for the includes-based Bambu profiles is in ~/Workspace/cad/spar-key-z-axis/scripts/print-r7/prepare-plate.py. Its printer settings belong to that project; reuse the resolution logic, not its hard-coded machine/material or API-meter values.

Inspect the exported 3MF, not only the UI dropdown: printer/nozzle, filament, build-plate type, temperatures, real machine-specific start/end G-code, model count, plate count, outside-bed flags, estimates and preview. Do not insert an A1 G-code fragment into a different machine's file. Resolve intentional preset overrides such as the selected bed explicitly.

Do not silently drop a missing inherited preset. Resolve it against the installed profile tree, preserve the child's overrides, and record any chosen replacement. Funnel Guide R4's old Prusa Generic PLA basis was missing; the recorded fallback was Generic PLA @System. That is a project-specific resolution, not a universal mapping. A newly confirmed PLA requirement takes precedence over an earlier ASA comparison profile; it does not also confirm the filament brand or printer.

Geometry provenance and print orientation

Export the changed parts from the checked CAD revision. Confirm units for the particular endpoint (the Onshape tessellated-facet coordinates used here were in meters and required ×1000); do not infer units solely from an STL extension. Check watertight positive-volume meshes and agreement with native CAD volume within a documented tessellation tolerance. Store the source revision, transforms, part IDs and file hashes with the exports.

Use a proper rotation for print orientation (orthonormal, determinant +1), not an accidental reflection. Translate the resulting lowest surface to bed Z=0 and check the footprint and protrusions. Verify 3MF archive integrity and build items, not just mesh object count: one object can have multiple instances. For an identical left/right part, state assembly quantity separately from the number actually placed on the exported plate.

Pick bed faces using the final geometry, including bosses, registration bars, recesses and stepped mating faces. A visually flat plate may actually stand on a small protrusion. Inspect required supports and their removal from fitting faces; a CAD support/strength heuristic is not a printed-load validation. Why a pose is strong, and how angled poses change support and bed contact, is covered in print orientation.

Report replacement parts relative to the user's actual printed revision. Count printed solids independently from reference hardware. Preserve known material, printer and readiness answers for the authorized task rather than asking again.

Support enabled is not support generated

An Orca report's support_used: "true" can describe an enabled setting even when the sliced model uses 0 mm³ of support. Inspect the generated extrusion paths, including support interfaces, and report actual material volume with units. Respect extrusion modes and exclude travel/retraction from material sums. Track M82/M83/G92 and retraction debt: positive E used to restore a retract is not deposited material. Count extrusion on actual XY paths in model layers, including G2/G3 arcs, and exclude startup/end purge. Cross-check totals against filament mass and density; do not trust a header unit when those disagree. Cross-check the layer preview; do not claim zero supports solely from a profile flag or a geometric overhang score. Time and mass remain slicer estimates for the recorded printer/material/settings.

A bridge-labelled path is not its unsupported span

The slicer can label a long solid-fill line above infill as Bridge. In Sparky, an 87.7 mm path crossed supporting gyroid; comparison with the preceding layer showed gaps under 2.6 mm among the 20 longest flagged paths. That did not prove all other paths safe or certify the part's strength.

For a suspicious report, locate the layer, object and actual G-code segment. Inspect support/infill underneath before concluding that the entire line spans air. A targeted previous-layer coverage check can help; document bead-width, layer/support-distance assumptions and which paths were sampled. Respect G-code coordinate/extrusion modes when parsing. Do not globally suppress bridge warnings. Include the configured support top gap: with 0.2-mm layers and a 0.2-mm gap, a bridge at Z3.2 can be supported by interface paths at Z2.8 while Z3.0 is intentionally empty. Count only actual support at that extra gap, not arbitrary lower model geometry. Inspect interface spacing and direction: a sparse interface parallel to a long bridge can leave long strips poorly supported. Consider denser contact layers for stepped fitting surfaces, then reslice and recheck their removability and coverage. Do not merely increase a verification tolerance.

Sparky R11 used three dense top-interface layers (spacing 0, top gap 0.2 mm). Its final longest 20 Bridge paths per plate had uncovered segments below 2.77 mm; these are project observations, not universal bridge limits. The reusable parsing and targeted coverage example is spar-key-z-axis/scripts/r11/check-print-paths.py in the CAD workspace. The earlier R7 checker did not handle all extrusion modes.

FDM process knowledge

Treat every generic value as a calibration candidate. A line-width multiple is a useful design aid, not a universal strength rule or a ban on gap fill. A 0.4 mm nozzle does not establish load capacity; section shape, material, print orientation, walls, infill and temperature all matter.

The supplied 0.84 / 1.26 mm thresholds are useful for finding small geometric details. They are not minimum safe carriage walls. Inspect the continuous load path and real interfaces in native CAD, and test a specimen where needed.

Declare the build orientation and actual usable plate. A nominal machine volume differs from a user-imposed plate boundary. Include support, brim and purge geometry in the final arrangement check.

An overhang angle is measured from vertical in these profiles. The 45-degree angle and 20 mm bridge span are uncalibrated search limits. The classifier cannot decide adhesion, cooling, support contact or surface quality. Existing deliberately supported mating faces can be the correct choice. The strength and surface consequences of a chosen pose are collected in print orientation.

Retain approved screw contours and fits. A generic insert table, plain pilot-hole diameter or hole compensation cannot replace a purchased insert's geometry or a custom crush-rib feature. State whether a clearance is radial, diametral or per side before using it.

A sketch text box, font em size, x-height and physical stroke width are different quantities. Check actual glyph geometry and sliced strokes; test small labels. A 0.3 mm engraving may cross one or two layers at a 0.2 mm layer height depending on orientation and slicing phase. Do not promise legibility from the nominal box size.

Use the current machine/material preset as evidence of intent, not as proof of a successful physical print. Record coupon material, nozzle, layer height, orientation and measured outcomes with a date before updating calibrated values.

Print orientation for FDM parts

Print orientation decides where a part is strong, where it looks clean, where it needs support and where it holds its dimensions. This article collects the transferable rules on that topic from one external reference: Stop Printing Flat: The 45° Secret for Stronger Parts by CNC Kitchen (Stefan Hermann), 26 October 2025. The knowledge is video-derived, not physically verified in this repository; every figure below is stated in that source under its own conditions, never a calibrated process value for our work. Reviewed from the author's subtitles and sampled frames; see Source and limits.

Why orientation changes strength

An FDM part is anisotropic. Bonds along a bead are polymer chains; bonds between layers are a partial re-melt of the layer below, so pulling layers apart is the weak direction. The source's core move is to align the principal tensile stress with the print lines, and where no orientation does that for all load directions, to accept an intermediate angle. The response is not linear: strength falls steeply away from flat, then flattens towards upright. A few degrees buy nothing, so if layer adhesion is the problem, tilt far enough to matter.

What the source measured

Tensile coupons, 0.2 mm layers, Prusa CORE One, AzureFilm green PLA, pulled on the author's own tensile tester.

Print angle Tensile strength stated in the source
0° (flat, load along the layers) 63 MPa
30° 44 MPa
45° 40 MPa (three coupons)
60° 36 MPa
90° (upright, load across the layers) 31 MPa

Further stated numbers: 45° is "27 % stronger" than the upright reference; layer adhesion is "typically around 50 %" of in-plane strength, higher for some materials and much lower for ABS printed with heavy cooling; the angled hose adapter gains "roughly 30 % more layer strength"; surfaces stay clean without support while slope angles stay "below roughly 45°". The plotted curve is a quadratic interpolation of the five points.

A second measured case is a hook, pulled to failure in three orientations. The flat (XY) hook carried by far the highest load; the 45° and 90° hooks failed at nearly the same, much lower load. Tilting did not help, it only moved the failure location, because the loading is not a simple uniaxial pull.

Getting an angled part to print

Angling costs bed contact, support and time, and adds its own failure mode.

  • Bed contact. Rotate into the wanted pose, then use the slicer's cut tool to shave a small flat off the corner that touches the plate, and add a brim. This is the source's routine when the CAD cannot be changed.
  • Support release is a real failure mode. All of the author's angled coupons printed with normal supports failed; those without supports printed cleanly. The mechanism given: even PLA curls, the loosely coupled support holds it, tension accumulates, the support lets go, the part springs up and the nozzle hits it.
  • Two fixes offered. Custom supports rigidly attached at only a few points (credited to Slant3D), or a reduced support-to-object XY distance with supports that are harder to remove but hold. The values visible in the slicer panel are the author's defaults, not a recommendation.
  • Split instead of tilt. The strongest structural example is the Multiboard system: rather than tilting a clip so its hooks print strong, the part is split down the middle, both halves print flat joined by a thin living bridge, and it is folded afterwards.

How this applies here

None of this changes our own process values; it sharpens decisions we already make.

The bed face is chosen before detailing. Orientation fixes the strength directions, the support strategy and which faces are perimeter faces, and all three get expensive once fillets, bosses and labels exist. Ask it at the first sketch, together with how the part is loaded; see print preparation and the cad-fdm-design skill.

Protected mating interfaces stay protected. Reorienting fixes a weak part but changes hole roundness, overhang quality and effective clearance on exactly the faces that mate. The source's adapter split during installation at its new angle because it was too tight, and only worked once the dimensions were corrected. A reorientation changes the interface; it is not free; see fits and retention.

Fits need their own coupon in the same print pose. A clearance measured on a flat-printed block does not carry over to the same feature printed at 45°. If the pose changes, the fit evidence is stale.

Slicer evidence beats assumptions. Support contact, bridges, bed contact area and the first layers of an angled part are visible in the sliced preview, and the source's failed prints show that plausible-looking support can still wreck a job. Video numbers are uncalibrated search limits in the sense of FDM profile guidance; confirming them belongs to verification.

Laser cutting

For small diode lasers (5–20 W optical, 450 nm) and desktop CO2 machines cutting 2–6 mm sheet. Profile: profiles/manufacturing/laser-diode-3mm.yaml. Laser parts are 2.5D: a plate with an outline, holes and engraving. In this design system they are the front plates, spacers, brackets and stacked "layered" bodies, usually combined with an FDM body.

1. Process facts

  • The beam removes a kerf of 0.1–0.3 mm; outlines come out smaller, holes larger, unless the CAM offsets the path by half the kerf (LightBurn "kerf offset").
  • The cut wall is slightly tapered (0.5–2° on thick material) and charred on wood; the bottom edge has more burn than the top.
  • Inner corners can be sharp (unlike CNC) — but sharp inner corners in acrylic are crack starters; 0.5 mm radius costs nothing visually.
  • Sheet thickness varies: "3 mm" plywood is 2.6–3.2 mm. Slots that must fit the sheet need the measured thickness, not the nominal.
  • Position accuracy of a decent machine is ±0.1 mm; repeatability better.

2. Kerf and fits

MDF 0.15–0.20 0.20–0.30

Design workflow: model everything nominal and let CAM compensate the kerf. Then:

Holes for screws: nominal ISO clearance (M3 → 3.4) works when kerf is compensated; without compensation cut them 0.1 smaller.

3. Joints

  • Tab and slot: tab length = sheet thickness (flush) or +1 mm (proud, as a style feature); tab width ≥ 2 × thickness; at least two tabs per edge; slot width from the fit table.
  • Finger joints (box corners): finger width 2–3 × thickness, odd finger count per edge so corners are symmetric; kerf compensation makes them firm without glue in plywood.
  • T-slot with nut: for M3 in 3 mm sheet: slot 3.4 wide, nut pocket 5.6 wide × 2.6 deep, pocket starts ≥ 6 mm from the edge; screw length = sheet + 3 + 2.
  • Stacked plates (2–6 layers through-bolted): the cleanest way to get a "layered" design language from a laser; every layer can be a different colour/material; align with two Ø3 dowel/screw holes per plate; inner layers carry pockets for PCBs and nuts.
  • Glue: wood glue for plywood, solvent (dichloromethane/acrylic cement) for acrylic; CA glue fogs acrylic.

4. Features, holes, engraving, text

  • Minimum structural feature width ≥ 1 × sheet thickness (plywood), ≥ 0.7 × in acrylic; decorative features down to 0.5 mm in acrylic, 1 mm in plywood (fibres tear).
  • Minimum hole Ø 1.0; below that the hole is a burn mark.
  • Distance between adjacent cuts ≥ 1 mm (heat merges them).
  • Vector engraving (outline, one pass): lines 0.1–0.2 mm wide; text down to 2 mm high.
  • Raster engraving (filled): text ≥ 3 mm high, strokes ≥ 0.5 mm; on plywood the fill chars unevenly — masking tape or a light pass; on black acrylic it gives a crisp frosted white — the best laser label there is.
  • Engraving depth is cosmetic (0.05–0.3 mm); for deep pockets use CNC.
  • Cut order: inner features first, outline last (otherwise the part drops and shifts).

5. Living hinges (plywood/MDF 3 mm)

Slot length 20–25 mm, slot spacing 1.5–2.0 mm across, gap between slot ends 1.0 mm (offset rows), minimum bend radius ≈ 10 × spacing. Acrylic hinges need thinner sheet (2 mm) and fatigue fast; use them for a one-time bend and glue.

7. Hybrids with printed parts

  • Front plate laser, body FDM: the plate gets the fine cut-outs, sharp corners and engraved labels FDM cannot do; the body gets the 3D features. Plate sits on a 0.6–1 mm reveal step in the printed body, fixed with the body's insert bosses. Design the reveal as a style feature.
  • Anodised aluminium plate, fibre- or diode-marked: 1–2 mm anodised sheet cut to size (or bought as blank), labels marked by laser, edges broken with a file. This is the honest way to the "machined instrument" look; a printed body carries it.
  • Acrylic display windows: 2 mm black or smoked cast acrylic, 0.2 mm slip fit in a printed pocket, glued at the corners.
  • Laser-cut TPU/EVA/silicone sheet: feet and gaskets; cut with the same kerf rules.

CNC machining

For desktop routers with 3.175 mm (1/8") shank tooling cutting plastics, plywood, aluminium plate and FR4. Profile: profiles/manufacturing/cnc-small-hobby.yaml. In this design system CNC is the process for plates with pockets, aluminium front panels, and anything that must be flat and dimensionally exact.

Process facts

  • Inner corners have a radius ≥ tool radius. A 3.175 mm end mill leaves R ≥ 1.6 in every pocket corner. If a square part must fit, use a dog-bone or T-bone relief; if a square corner must look square, use a smaller tool for a corner pass (1 mm end mill → R0.5).
  • Outer corners can be sharp.
  • Pocket depth per tool ≤ 3 × tool diameter (chatter, deflection); through-cuts in 6 mm plate with a 3 mm tool are fine in plastic/wood, marginal in aluminium.
  • Parts need holding: tabs, double-sided tape, clamps outside the outline, or a vacuum. Leave 3 mm of stock around the outline for clamps.
  • Surface finish depends on step-over; a 0.1 mm finishing pass gives a "machined" look with visible tool paths — that is a texture, decide whether the style wants it.
  • Accuracy ±0.05–0.1 mm on a rigid machine; ±0.2 on light gantries.

SLA and MSLA

For hobby MSLA printers (Elegoo, Anycubic, Phrozen; 35–50 µm pixels, 0.05 mm layers) with standard or ABS-like resins. Profile: profiles/manufacturing/sla-generic.yaml. In this design system SLA is mostly the "fine parts" process: knob caps, buttons, small bezels, logos, gears — pieces where FDM's 0.4 mm resolution or layer lines would show.

Process facts

  • Resolution is excellent (features 0.2–0.3 mm), but everything needs supports except what sits directly on the plate, and every support leaves a mark. Orientation and support placement decide the cosmetic result more than any dimension.
  • Resin cures with 0.2–0.5 % shrinkage and continues to harden for a day; thin walls warp during post-cure if unsupported.
  • Parts are isotropic (no layer-bond weakness) but standard resin is brittle; use ABS-like or tough resin for anything clipped or screwed.
  • Hollow parts trap resin; they need drain holes and get washed inside.
  • Surfaces printed at a steep angle to the plate look best; horizontal top faces show "pixel" texture, overhanging faces show support scars.

  • No fillets under 0.3 mm — they vanish; edge breaks of 0.3–0.5 read as "moulded".
  • Text: debossed 0.2–0.3 deep is crisp; embossed 0.3 proud is fine; inlays are possible by pausing and painting/filling.
  • Screws: self-tapping into tough resin only; prefer press-fit steel pins or inserts set with epoxy (heat-set inserts crack resin).
  • Snap-fits only in tough/flexible resins, with 2× the FDM safety margins.

Calibration coupon

A 40 × 40 × 3 plate with holes Ø0.5–3 in 0.25 steps, pins Ø0.3–2, slots 0.2–1.0, text 1.5–3 mm; plus a cube-in-cube fit test with 0.05–0.3 gaps. Adjust exposure until Ø1 hole and Ø1 pin both hit nominal ± 0.05; set holes.compensation to the residual.

Mosey 0.1 combines a clear silhouette with large, tactile controls and calm colour fields. A recess, bail, broad facet or folded shell gives an object character while supporting its use.

Application and verification

  1. Record function, purchased parts, assembly and protected surfaces.
  2. Choose a form variant and one useful main detail.
  3. Shape free exterior surfaces; assign colour roles and calm parting lines.
  4. Apply radii and labels only to named cosmetic regions.
  5. Check mechanics and manufacturability against the actual process. Preserve raw findings and classify their significance.
  6. Produce colour chips and an appropriate hand or functional coupon before treating values as calibrated.

The existing STEP checker detects radii but does not automatically know their visual or functional roles. A radius outside the family is initially a finding to classify. The generic style-tile generator also represents neither the three form variants nor verified Mosey mechanics.

A suitable instruction is: “Use Mosey 0.1 in the broad_facet variant. Preserve the specified interfaces and load paths. Shape the free enclosure surfaces with a few broad facets, one large adjuster and the roles Chalk / Cobalt / Lilac. Document deviations and check against the actual manufacturing profile.”

What should make the design recognisable

The silhouette remains understandable without colour. The characteristic detail helps the user. Colour fields follow clear roles. Seams and labels do not dominate the main form. Visible metal parts may remain metal; vents, screws or a camera opening are added only when function requires them.

A standard pastel box alone does not fully express this language. Nor does adding as many flower-shaped knobs, arches and grooves as possible. Its identity comes from the combination of calm form, tactile controls and one useful design idea.

Lessons from projects

The rules below were distilled from real design work and are stated generically, so that they apply to the next part rather than to the one that produced them. The originating project is named only as provenance at the end of each section; it is not a reference you can look up here, and its figures, renders and measured results are not part of this repository's evidence. Nothing in these projects has been re-verified for general use, so treat every number that appears below as belonging to that study alone. Where a rule already has a maintained home in another article, it is stated once and linked rather than repeated.

Design language must not touch protected interfaces

Keep visual rules, process profile and protected interfaces in separate layers, and resolve them in that order of authority. A grid, radius family or accent colour selects and signals; it never moves a mounting axis, thins a loaded carrier or reduces engagement. Apply facets, labels and accents to named faces chosen per part, not by a blanket rule across all edges. This prevents the common failure in which a styling pass silently changes a fit that other parts depend on, and it prevents the opposite failure of refusing a deliberate manufacturing choice (a supported print, for example) because it looks untidy. To apply it, list the protected interfaces before styling and re-check them afterwards; a product's character should be visible across the part family, not on every chamfer. See the design-system skill and the precedence table in the shared core.

Origin: Sparky X/Z unit, R13→R14 comparison.

Assembly inventory is not the CAD part count

Treat CAD occurrences, purchased-component count and assembly handling units as three separate layers, each counted for its own purpose. A multipart marker or a complete purchased bearing is one handling unit, not a set of individually assembled pieces; conversely one CAD body may be several inventory lines. Reconcile the layers explicitly instead of deriving one from another. The failure this prevents is a manual that instructs a build no one can perform, because the count came from the model tree rather than from the hands doing the work. Evidence is an accessible fastener sequence per stage, not a plausible final pose; in one documented revision the same assembly yielded 45 CAD occurrences, 43 handling units and 20 inventory entries, and those figures belong to that study only. An exploded animation explains a step; it does not establish an insertion path. See assembly review and the assembly-manual skill.

Origin: C2 Channel assembly manual, documented revision.

A simulation result belongs to its exact model

State geometry revision, contact model, material and its assumptions, print orientation and load case together, or do not state the result at all. A displacement figure is a property of that combination; carrying it into a later revision, a different support arrangement or a different material is a new claim requiring a new run. This prevents "FEM checked" from becoming a label detached from any traceable input. In practice: record solver progress, equilibrium and sensitivity to contact stiffness, name what is still open (mesh refinement, creep, yielding), and keep the study's own numbers marked as belonging to it. One documented contact study reported roughly 3.97 mm maximum vertical displacement under an assumed 1 kg load with assumed friction; that value is valid only for that geometry and load case. The general distinction between simulation, slicing and physical testing is maintained in verification.

Origin: Distributor contact study, R8.

A scan is a hypothesis until measured

Keep photos, raw scans, reference frames and the functional replacement model as four distinct sources, and never let a smoothed surface stand as a dimension. Cleaning, registration and canonical alignment come before any measurement; leftover fixture or turntable geometry corrupts registration, and attached markers are not features of the part. Reconstruct a simple functional form and then measure its deviation, rather than tracing every scan irregularity. The failure prevented is a model that reproduces noise faithfully and function poorly. Check functional surfaces and local openings individually: a global average deviation hides exactly the local errors that matter, and sample points inside CAD triangles so tessellation structure is not mistaken for geometry. See the scan reconstruction skill.

Origin: LINAK motor-cover scan reconstruction.

Compensation has one owner

Assign each manufacturing correction, kerf, hole allowance, shrink or scale, to exactly one step in the chain and record where that is. Either the model carries nominal geometry and CAM offsets the path, or the exporter emits compensated contours and CAM must not offset again; both are valid, applying both is not. This prevents the double-correction that turns a good fit into a loose one without any visible modelling error. To apply it, separate nominal geometry, material thickness, manufacturing contour and sheet layout as distinct artifacts, and state the owner in the workflow description before the first cut. Kerf values and the nominal-plus-CAM convention are maintained in laser cutting.

Origin: File-trolley laser extension, export workflow.

Variants isolate one question

Build variants on a shared frame so that each set differs in one respect only, and keep form questions apart from mechanical ones. Form studies need identical cameras, scale and lighting; mechanical comparisons need identical boundary conditions, and the two must not be read from the same picture. The failure prevented is a decision made on an attractive render or a high simulated speed that came from a changed camera or a changed contact assumption rather than from the design. Applying it means parameter-driven geometry over duplicated models, dedicated calibration coupons for anything you intend to measure, and treating a physics prototype's output as a hypothesis until it is calibrated against a printed specimen. See construction patterns for the patterns a shared frame usually reuses.

Origin: Bristlebot variant study, Fusion branch.

Joint families share a principle, not dimensions

Describe a joint by its function, interface and limitations; the edge treatment, radii and wall thicknesses that a family happens to use are an optional profile, not part of the definition. Reusing a fork-and-tongue interface across a product family is sound; reusing its dimensions on a new material, load or print pose is not, and each such change requires its own evidence. This prevents a validated joint from being credited with validation it never had. Note also that a project preference (printed hand-operated threads, for example) is a preference and not a prohibition, a purchased ball joint or a metal fastener remains available where it is the better answer. Comparing dimensions between two modelling routes does not establish that all surfaces are equivalent. See joints and fits and retention.

Origin: Modular camera-arm mount family, fork-and-tongue interfaces.
