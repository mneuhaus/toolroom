# Tile clip sockets — does a scaled pocket still take its scaled clip?

Terrain systems such as OpenLOCK and Dragonbite define a clip-in-pocket joint at one fixed size. Scaling a whole tile set up or down (bigger terrain, thicker walls, a coarser nozzle) scales the pocket and the clip together — but the printer's line width, layer height and minimum wall do not scale. This lab asks two narrow questions: **does the scaled clip still insert into the scaled pocket without protruding**, and **at what scale does a specific FDM process floor (a clearance, an interference, a minimum wall) start to bite**? It does not ask whether the printed parts actually fit, hold together or survive a load — see [what a result is not](#what-a-result-is-not).

The reconstructed geometry and its sources are documented in [Tile clip joints: clip-in-pocket connections for modular terrain](../../knowledge/construction/tile-clip-joints.md). This lab is the reproducible half of that article: everything below is generated by the scripts in this folder, not modelled by hand.

## What is built

For every scale in `{0.5, 0.75, 1.0, 1.5, 2.0}` and every system, the generator builds:

- **OpenLOCK floor coupon** — a 25.4 × 25.4 × base tile with one lying pocket per edge (mouth, taper, neck, chamber, barb).
- **OpenLOCK wall coupon** — a 25.4 × 12.7 × 25.4 tile with a base through-pocket and a vertical side-lock pocket on each end.
- **OpenLOCK clip** — bar, prongs, barbs, eye slot.
- **Dragonbite floor coupon** — a 25.4 × 25.4 × base tile with one lying throat/cavity pocket per edge (post, head, neck).
- **Dragonbite clip** — bar, jaws, gap.

Each coupon is exported as STEP and STL, and its pocket negative (and, for the OpenLOCK wall, the side-lock negative) is exported as STEP only, under `exports/s{scale}/`. STL uses a coarse tolerance (0.05 mm linear, 0.5 rad angular) so the whole `exports/` tree stays well under 15 MB.

## How to run

```sh
uv run python labs/tile-clip-sockets/build.py --scale 1.0                # one scale, default through/no-supports
uv run python labs/tile-clip-sockets/build.py --scale 1.0 --variant blind --supports --chamfer --enforce
uv run python labs/tile-clip-sockets/build.py --all                      # all five scales, writes results/
uv run python labs/tile-clip-sockets/verify.py                           # re-hashes exports, re-imports every STEP, checks the SVG
```

`--variant through|blind` selects an open-bottom pocket (chamber cut through the base, OpenLOCK "through") or a closed one (Dragonbite's 2020 port block, 1.4 mm floor). `--supports` adds the built-in support bars / bridging ribs. `--chamfer` adds a proposed 0.4 mm lead-in at the mouth corners. `--enforce` raises the base height whenever the roof would otherwise sit below its minimum. `--v43-bar` swaps the OpenLOCK clip bar width for the older v4.3 value (14.0 mm) instead of the current v5.4 value (13.2 mm). `--all` always regenerates `results/summary.json` and `results/scaling-table.md`; a single `--scale` run writes `results/summary-s{scale}.json` instead and does not touch the two combined files.

## Parameter model

`spec.py` holds three dataclasses, none of them derived from this lab's own guesses beyond what is marked "proposed":

- **`Process`** — FDM floors that do **not** scale with geometry: nozzle width, layer height, a total XY clearance (mouth/throat minus clip bar), a total Z clearance (pocket height minus clip thickness), a minimum total interference across both flanks (one line width), roof/floor/rim minimums, and a minimum clip thickness in layers.
- **`OpenLock`** — every profile dimension of the floor pocket, wall pocket, side-lock pocket and clip, each carrying a `sources` string that points at a specific finding (`var/research/openlock/findings.md` §6–9).
- **`Dragonbite`** — the same for the Dragonbite throat/cavity/post and clip (`var/research/dragonlock/findings.md` §3–5).

`spec.scaled(obj, S)` multiplies every float field (and every element of tuple fields) by `S`; integer/bool fields and `sources` pass through unchanged. This is a data-only operation — it says nothing about whether the scaled numbers still make sense against the process floors. That comparison happens in `build.py`.

## Scaling rules

Profile dimensions scale by `S`. Process floors from `spec.Process` never scale. After scaling, `derive_openlock` / `derive_dragonbite` in `build.py` compare each scaled quantity against its floor and record the outcome as `{quantity, scaled_value, floor, applied_value, action}` in `dimensions["adjustments"]`:

| Floor | Owner when it bites | Action |
| --- | --- | --- |
| Z clearance (pocket/throat height − clip thickness) | Clip | shrink clip thickness |
| XY clearance (mouth/throat width − clip bar width) | Clip | shrink clip bar width |
| Interference (OpenLOCK barb − neck; Dragonbite head − bite gap) | Clip | grow the barb / close the bite |
| Clip thickness minimum (4 layers) | — | flag only |
| Support bar / bridging rib width | Support feature | widen to the floor (only with `--supports`) |
| Roof (base height − pocket/throat ceiling) | Base | flag only, unless `--enforce`: raise the base height to `pocket/throat_z1 + roof_min` |
| Floor (pocket z0 / Dragonbite blind floor) | Base | flag only |
| Rim side and rim depth | Base | flag only |

The pocket geometry itself is never shrunk to satisfy a clearance or interference floor — **the clip is always the owner** that gets adjusted, so the socket stays true to its reconstructed source dimensions at every scale. Only `--enforce` changes the pocket-adjacent geometry (the base height, to protect the roof). Every non-`"none"` action also appears in `dimensions["flags"]` as `quantity:action`.

## Verification

`verify.py` (`verify_case`, called from `build.py` for every case, and standalone against `results/summary.json`) checks, per scale and system:

- **Insertion**: the clip is placed at its inserted pose (bar centred on the joint plane between two mirrored coupon halves). Protrusion volume outside the pocket negative must be below `TOL` (1e-3 mm³) everywhere except the declared barb/jaw region, where a specific expected interference volume is checked instead; a separate transit-interference probe confirms the clip must deform somewhat to slide from the mouth to the seated pose (compliance is expected, not a defect).
- **Section measurements**: mid-height pocket widths (mouth, taper, neck, chamber / throat, cavity, post head), depth, floor and roof thickness, rim side width, and clip stations (bar, prong/jaw, barb/bite, tip, eye/gap widths, thickness, length) — all measured on the actual solid via probe-box voids/intersections, compared against `spec × S` within `MEAS_TOL` (0.02 mm).
- **Roof/floor/rim** against the `Process` floors.
- **Volumes and validity** of every exported solid (single body, closed, valid).
- **SHA-256** of every exported file, recorded in `summary.json["cases"][*]["exports"]`; standalone `verify.py` re-hashes, re-imports every STEP with `import_step`, and re-checks the volume, plus validates the SVG as parseable XML with a `viewBox`.

Results land in **`results/summary.json`** (one list of cases across all five scales, each with `dimensions`, `adjustments`, `flags`, `insertion`, `measurements`, `validity`, `volumes`, `exports`) and **`results/scaling-table.md`**, reproduced below.

## Merged socket / hybrid clip (scale 1 only)

`merged.py` (run standalone: `uv run python labs/tile-clip-sockets/merged.py`) extends the lab with a
Toolroom design rather than another OpenLOCK/Dragonbite reconstruction: a "merged" socket that keeps the
OpenLOCK pocket envelope (`spec.py`'s `OpenLock` numbers, reused verbatim) but roofs the chamber with a
1.2 mm top plate carried on a central Ø2.0 post, plus a "hybrid" clip that keeps the OpenLOCK outline and
reshapes its eye slot into a compliant jaw around that post (`spec.Merged` in `spec.py`). It builds:

- three 25.4 x 25.4 tile coupons (merged with/without post, plus an OpenLOCK-reference control with the
  same top plate so it prints),
- a 25.4 x 12.7 x 25.4 wall coupon (merged and reference), each in both a standing and a lying print pose,
- a 50.8 mm six-face pocket cube (one merged pocket per face, thin axis rotated per face, engraved labels),
- 6 hybrid clips (thickness x grip matrix: t in {3.5, 3.7, 3.9} mm, grip standard/tight) plus one reference
  OpenLOCK clip, each engraved with its own label.

All of it is cross-checked at scale 1 in `merged.py` (protrusion, seated/transit interference, post-to-
eye-slot clearance, section measurements, wall/cube spot-checks and an analytic printability/bridging
report) — results in [`results/merged.json`](results/merged.json) and
[`results/merged-table.md`](results/merged-table.md) — and packaged for printing under
[`print/`](print/README.md) (STL at fine tolerance, `manifest.json` with a sha256 per file, and `print/README.md`
with print settings, an orientation/bridging guide and a test protocol). This part of the lab does not
scale; it stands on its own next to the OpenLOCK/Dragonbite scaling study above.

## What a result is not

Every number here comes from solid-body geometry checked against other solid-body geometry, in Build123d, on the dimensions this lab reconstructed from public documentation (see the [source article](../../knowledge/construction/tile-clip-joints.md) for provenance and its limits). None of it has been printed. A passing insertion check means the modelled clip solid does not protrude from the modelled pocket solid beyond the stated tolerance at the stated pose — it says nothing about:

- **Physical fit**: real filament shrinkage, elephant's foot, layer-line roughness and slicer behaviour are not modelled; the `Process` floors are proposed engineering margins, not measured clearances (see their `sources` in `spec.py`).
- **Assembly force or compliance**: the transit-interference probe only checks that *some* deformation is geometrically required between the mouth and the seated pose; it does not model material compliance, so it cannot say whether that deformation is achievable by hand or would snap the part.
- **Strength or retention**: no load, peel or fatigue case is applied. The retention mechanism (barb behind the neck, jaws around the post head) is only checked for its expected interference volume, not for whether that interference actually holds under a pulling force.
- **Printability**: bridging over the chamber/cavity void, support removal and orientation are outside this check; `--supports` only adds the reference support/rib geometry as extra solid, it does not verify it prints cleanly.

`summary.json` records this explicitly: `"physical_print": "not performed"`, `"physical_fit": "not measured"`, `"strength": "not tested"`.
